================================================================================
DEEPFAKE DETECTOR — CONFIGURATION GUIDE
================================================================================

This document explains how to customize every configurable part of the
platform — AI models, database backends, payment gateway, email, storage,
and rate limiting.

All paths in this document are relative to the project root:
    e:\AI Projects\deepfake-detector\

After ANY change to .env or any backend file, recreate the affected
containers:
    docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend worker flower

After changes to backend Python code (anything under backend/), you must
also rebuild the image first:
    docker compose -f infra/docker-compose.yml --env-file .env build backend
    docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend worker flower

After changes to the frontend code:
    docker compose -f infra/docker-compose.yml --env-file .env build frontend
    docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate frontend

================================================================================
1. AI MODELS
================================================================================

Every detection module is a thin wrapper around a Hugging Face transformers
pipeline. None of them require API keys. The model name is read from an
environment variable, so you can swap models without changing code.

CURRENT DEFAULTS
----------------
  Image  : prithivMLmods/Deep-Fake-Detector-v2-Model      (image-classification)
  Video  : same as image, run on 16 sampled frames
  Audio  : MelodyMachine/Deepfake-audio-detection-V2      (audio-classification)
  Text   : roberta-base-openai-detector                   (text-classification)
  URL    : same as text, run on extracted page body

ENVIRONMENT VARIABLES
---------------------
Add these to .env to override the defaults:

  DEEPFAKE_IMAGE_MODEL=<huggingface-repo-id>
  DEEPFAKE_AUDIO_MODEL=<huggingface-repo-id>
  DEEPFAKE_TEXT_MODEL=<huggingface-repo-id>

(Video and URL modules reuse Image and Text respectively.)

STEP-BY-STEP: SWAP THE IMAGE MODEL
----------------------------------
1. Pick a Hugging Face image-classification model that outputs
   "real"/"fake" style labels. Examples:
     - umm-maybe/AI-image-detector
     - dima806/deepfake_vs_real_image_detection
     - Wvolf/ViT_Deepfake_Detection

2. Add to .env:
     DEEPFAKE_IMAGE_MODEL=umm-maybe/AI-image-detector

3. Recreate worker (it does the inference, not the API):
     docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate worker

4. The worker downloads the new model on the first scan
   (cached to the `models_cache` Docker volume).

STEP-BY-STEP: SWAP THE AUDIO MODEL
----------------------------------
Choose any Hugging Face audio-classification model. Examples:
  - MelodyMachine/Deepfake-audio-detection-V2  (default)
  - mo-thecreator/Deepfake-audio-detection
  - motheecreator/Deepfake-audio-detection

  DEEPFAKE_AUDIO_MODEL=motheecreator/Deepfake-audio-detection
  docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate worker

STEP-BY-STEP: SWAP THE TEXT MODEL
---------------------------------
Choose any Hugging Face text-classification model. Examples:
  - roberta-base-openai-detector            (default)
  - Hello-SimpleAI/chatgpt-detector-roberta
  - desklib/ai-text-detector-academic-v1.01
  - PirateXX/AI-Content-Detector

  DEEPFAKE_TEXT_MODEL=Hello-SimpleAI/chatgpt-detector-roberta
  docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate worker

USING A GATED / PRIVATE MODEL
-----------------------------
Some HuggingFace models (e.g. Llama-derived) require accepting a license
and using an access token. If you ever need that, add to .env:

  HF_TOKEN=hf_yourTokenHere
  HUGGING_FACE_HUB_TOKEN=hf_yourTokenHere

The transformers library auto-picks these up. The bundled defaults do NOT
need this.

PRE-WARM ALL MODELS (avoid slow first scan)
-------------------------------------------
After bringing up the stack:

  docker exec deepfake-detector-worker-1 python -c "from transformers import pipeline; pipeline('image-classification', model='prithivMLmods/Deep-Fake-Detector-v2-Model'); pipeline('audio-classification', model='MelodyMachine/Deepfake-audio-detection-V2'); pipeline('text-classification', model='roberta-base-openai-detector'); print('all cached')"

This downloads ~1.2 GB once into the models_cache volume.

DEEPER CHANGES (different prediction logic)
-------------------------------------------
If you want to change HOW the score is computed (not just which model),
edit the detector source files:

  ai-services/image/detector.py    — image classification + label fusion
  ai-services/video/detector.py    — frame sampling count, aggregation
  ai-services/audio/detector.py    — sample rate, label whitelist
  ai-services/text/detector.py     — classifier+burstiness fusion (currently 70/30)
  ai-services/url/detector.py      — URL fetching, metadata heuristics

Then rebuild + recreate worker:
  docker compose -f infra/docker-compose.yml --env-file .env build backend
  docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate worker

VIDEO FRAME COUNT
-----------------
In ai-services/video/detector.py:

  NUM_FRAMES = 16

Increase for higher accuracy (slower), decrease for faster scans.

2. DATABASE
================================================================================

The default is PostgreSQL 16 in a Docker container. The code uses SQLAlchemy
2.0 ORM, so it CAN run on MySQL, MariaDB, or SQLite — but a few small
changes are needed because the current code uses Postgres-specific column
types (UUID, JSONB) and a Postgres advisory lock.

Postgres-specific things in the code:
  - sqlalchemy.dialects.postgresql.UUID    (in 6 model files)
  - sqlalchemy.dialects.postgresql.JSONB   (scans.result_payload, audit_logs.metadata_json)
  - "SELECT pg_advisory_xact_lock(...)"    (in app/main.py lifespan)
  - Native enum types created via SQLAlchemy SqlEnum
  - Driver psycopg2-binary

----------------------------------------------------------------------
2.1  STAY ON POSTGRES — change credentials, host, or use a cloud DB
----------------------------------------------------------------------

This needs ZERO code changes. Just edit .env.

A) LOCAL DOCKER POSTGRES (default)

   POSTGRES_USER=deepfake
   POSTGRES_PASSWORD=deepfake_pw
   POSTGRES_DB=deepfake_db
   POSTGRES_HOST=postgres
   POSTGRES_PORT=5432
   DATABASE_URL=postgresql+psycopg2://deepfake:deepfake_pw@postgres:5432/deepfake_db

B) EXTERNAL / CLOUD POSTGRES (Supabase, Neon, RDS, Railway, etc.)

   Step 1 — get the connection string from the provider, e.g.:
       postgresql://USERNAME:PASSWORD@HOST:5432/DBNAME?sslmode=require

   Step 2 — set DATABASE_URL in .env (note the +psycopg2 driver):
       DATABASE_URL=postgresql+psycopg2://USERNAME:PASSWORD@HOST:5432/DBNAME?sslmode=require

   Step 3 — disable the local Postgres container.
       Edit infra/docker-compose.yml:
         a) Comment out the entire `postgres:` service block.
         b) Remove `postgres` from the `depends_on:` lists of the
            `backend` and `worker` services.

   Step 4 — recreate:
       docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend worker

   Step 5 — verify:
       curl http://localhost:8000/health

C) SUPABASE (specific example)

   1. Create a project at https://supabase.com.
   2. Settings → Database → "Connection string" → choose URI mode.
   3. Replace the placeholder password with the one you set during creation.
   4. In .env:
       DATABASE_URL=postgresql+psycopg2://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:6543/postgres
   5. Comment out `postgres:` service and recreate.

D) NEON (specific example)

   1. https://neon.tech → create project.
   2. Copy the "connection string" (has ?sslmode=require already).
   3. In .env:
       DATABASE_URL=postgresql+psycopg2://USER:PASS@ep-xxx.us-east-2.aws.neon.tech/neondb?sslmode=require
   4. Comment out `postgres:` service and recreate.

----------------------------------------------------------------------
2.2  SWITCH TO MYSQL / MARIADB
----------------------------------------------------------------------

This requires small code changes because Postgres UUID / JSONB types are
not portable. Follow ALL steps below in order.

Step 1 — Driver

   Edit backend/requirements.txt. Replace:
       psycopg2-binary==2.9.10
   With:
       PyMySQL==1.1.1
       cryptography==43.0.3

Step 2 — Model files: replace UUID and JSONB with portable equivalents

   In ALL of these files:
       backend/app/models/user.py
       backend/app/models/subscription.py
       backend/app/models/scan.py
       backend/app/models/usage.py
       backend/app/models/audit.py
       backend/app/models/malicious_hash.py

   Find:
       from sqlalchemy.dialects.postgresql import UUID
       (and possibly JSONB)
   Replace with:
       from sqlalchemy import Uuid, JSON

   Find every:
       UUID(as_uuid=True)
   Replace with:
       Uuid

   Find every:
       JSONB
   Replace with:
       JSON

   `Uuid` is SQLAlchemy 2.0's portable type — it stores as native UUID on
   Postgres and as CHAR(36) on MySQL/SQLite automatically.

Step 3 — main.py: skip the Postgres advisory lock on non-Postgres backends

   Edit backend/app/main.py. Replace the lifespan body with:

     async def lifespan(app: FastAPI):
         log.info("app.starting", env=settings.app_env)
         if not settings.is_production:
             with engine.begin() as conn:
                 if engine.dialect.name == "postgresql":
                     conn.execute(text("SELECT pg_advisory_xact_lock(:k)"),
                                  {"k": _SCHEMA_LOCK_ID})
                 Base.metadata.create_all(bind=conn)
         yield
         log.info("app.stopping")

Step 4 — .env

   Replace the Postgres section with:

     DATABASE_URL=mysql+pymysql://deepfake:deepfake_pw@mysql:3306/deepfake_db

Step 5 — docker-compose.yml

   Edit infra/docker-compose.yml. Replace the `postgres:` service with:

     mysql:
       image: mysql:8.4
       environment:
         MYSQL_DATABASE: deepfake_db
         MYSQL_USER: deepfake
         MYSQL_PASSWORD: deepfake_pw
         MYSQL_ROOT_PASSWORD: rootpw
       volumes:
         - mysql_data:/var/lib/mysql
       ports:
         - "3306:3306"
       healthcheck:
         test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
         interval: 5s
         retries: 10
         timeout: 5s

   And in `volumes:` at the bottom, replace `postgres_data:` with `mysql_data:`.

   Update `depends_on` of backend and worker — replace `postgres` with `mysql`.

Step 6 — Rebuild and bring up

     docker compose -f infra/docker-compose.yml --env-file .env down -v   # ⚠️ wipes Postgres data
     docker compose -f infra/docker-compose.yml --env-file .env build backend
     docker compose -f infra/docker-compose.yml --env-file .env --env-file .env up -d

Step 7 — Verify

     docker exec -it deepfake-detector-mysql-1 mysql -u deepfake -pdeepfake_pw deepfake_db -e "SHOW TABLES;"

   Should list: users, subscriptions, scans, usage_records, audit_logs, malicious_hashes.

For MARIADB the steps are identical — just use `image: mariadb:11`.

----------------------------------------------------------------------
2.3  SWITCH TO SQLITE (single-machine dev)
----------------------------------------------------------------------

Best for local dev — no separate database container needed.

Step 1 — apply Steps 1–3 from MySQL section above (portable types,
         dialect-aware lock).
         For Step 1 (driver), no extra package is needed; sqlite3 is in stdlib.
         You can REMOVE psycopg2-binary if you want.

Step 2 — Loosen engine config in backend/app/db/session.py:

     connect_args = (
         {"check_same_thread": False}
         if settings.database_url.startswith("sqlite")
         else {}
     )
     engine = create_engine(
         settings.database_url,
         pool_pre_ping=True,
         connect_args=connect_args,
         future=True,
     )

Step 3 — .env:

     DATABASE_URL=sqlite:////srv/data/deepfake.db

   (The four slashes are intentional — `sqlite:///` is relative,
   `sqlite:////` is absolute.)

Step 4 — Add a writable volume for the database file.
   In infra/docker-compose.yml under the `backend` and `worker` services'
   `volumes:` blocks, add:
       - sqlite_data:/srv/data
   And add to top-level `volumes:`:
       sqlite_data:

Step 5 — Comment out the entire `postgres:` service in docker-compose.yml
         and remove `postgres` from `depends_on` of backend and worker.

Step 6 — Rebuild and recreate:
     docker compose -f infra/docker-compose.yml --env-file .env build backend
     docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend worker

----------------------------------------------------------------------
2.4  MIGRATING EXISTING DATA OUT OF POSTGRES
----------------------------------------------------------------------

If the running Postgres already has users/scans/etc., back it up first:

  docker exec deepfake-detector-postgres-1 pg_dump -U deepfake -d deepfake_db --data-only --inserts > data.sql

Restore into another Postgres:
  psql "postgresql://USER:PASS@new-host:5432/db" < data.sql

For Postgres → MySQL or Postgres → SQLite, use pgloader:
  https://pgloader.io/

----------------------------------------------------------------------
2.5  PRODUCTION SCHEMA MANAGEMENT
----------------------------------------------------------------------

In dev, tables are auto-created by SQLAlchemy's create_all() on startup
(see backend/app/main.py). In production (APP_ENV=production), this is
skipped. Use Alembic for real migrations:

  docker exec -it deepfake-detector-backend-1 bash
  alembic init alembic
  alembic revision --autogenerate -m "init"
  alembic upgrade head

3. PAYMENT GATEWAY (RAZORPAY)
================================================================================

Razorpay is integrated for paid plan upgrades (Pro, Enterprise). The
integration uses Razorpay's "Standard Checkout" — the user's card data
NEVER touches our backend; Razorpay handles all PCI work.

WITHOUT KEYS, the platform still fully works — just upgrade attempts
return HTTP 503 "Razorpay is not configured". Auth, scans, history all
function on the free plan.

----------------------------------------------------------------------
3.1  GET RAZORPAY KEYS
----------------------------------------------------------------------

Step 1 — Sign up at https://razorpay.com (Indian businesses; international
         payments require additional KYC).

Step 2 — Dashboard → Settings → API Keys → Generate Test Keys.
         You will get:
             Key Id     : rzp_test_XXXXXXXXXXXX
             Key Secret : YYYYYYYYYYYYYYYY
         Save the secret immediately — it is shown only once.

Step 3 — For production, complete KYC, then generate Live keys
         (rzp_live_XXXXXXXXXXXX).

----------------------------------------------------------------------
3.2  CONFIGURE THE BACKEND
----------------------------------------------------------------------

Edit .env:

   RAZORPAY_KEY_ID=rzp_test_XXXXXXXXXXXX
   RAZORPAY_KEY_SECRET=YYYYYYYYYYYYYYYY
   RAZORPAY_WEBHOOK_SECRET=    # only after you set up webhook (step 3.5)

Recreate backend:

   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend

Verify (inside backend container):

   docker exec deepfake-detector-backend-1 python -c "from app.services.payments import get_payments; print('enabled:', get_payments().enabled)"

   Expect:  enabled: True

----------------------------------------------------------------------
3.3  CONFIGURE THE FRONTEND
----------------------------------------------------------------------

The frontend uses the Razorpay Standard Checkout JS library and needs
ONLY the public Key Id (the secret stays on the backend). Add to .env:

   NEXT_PUBLIC_RAZORPAY_KEY_ID=rzp_test_XXXXXXXXXXXX

Rebuild + recreate frontend (Next.js bakes NEXT_PUBLIC_* at build time):

   docker compose -f infra/docker-compose.yml --env-file .env build frontend
   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate frontend

----------------------------------------------------------------------
3.4  PAYMENT FLOW (how it works internally)
----------------------------------------------------------------------

   1. User clicks "Upgrade to Pro" on /dashboard/subscription.
   2. Frontend calls POST /subscription/order with {plan: "pro"}.
   3. Backend (PaymentsService.create_order) calls Razorpay's Orders API
      and returns {id, amount, currency, ...}.
   4. Frontend opens Razorpay Checkout with that order id.
   5. User pays. Razorpay calls back with razorpay_payment_id, razorpay_order_id,
      and razorpay_signature.
   6. Frontend POSTs them to /subscription/verify.
   7. Backend verifies the HMAC signature using the Key Secret. If valid:
        - subscription.status -> active
        - subscription.plan -> pro / enterprise
        - period dates updated
   8. User now has the new plan (quota changes, file size limits change).

----------------------------------------------------------------------
3.5  WEBHOOK (recommended for production)
----------------------------------------------------------------------

The /subscription/verify endpoint covers the happy path. But if a user
closes the browser after paying, you may miss the confirmation. Webhooks
solve this — Razorpay POSTs the event server-to-server.

Step 1 — Pick or generate any random secret string (this is YOUR secret,
         not Razorpay's). Save it to .env:
             RAZORPAY_WEBHOOK_SECRET=some-long-random-string

Step 2 — Expose your backend publicly. For dev:
             ngrok http 8000
         Note the https:// URL it gives you.

Step 3 — Razorpay Dashboard → Settings → Webhooks → Add New Webhook.
         URL:    https://YOUR-PUBLIC-URL/subscription/webhook
         Secret: (same string you put in .env)
         Events: payment.captured, payment.failed, order.paid

Step 4 — Recreate backend so it picks up the new env:
             docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend

The verify_webhook_signature() method in app/services/payments.py
validates HMAC-SHA256.

----------------------------------------------------------------------
3.6  CHANGE PLAN PRICES
----------------------------------------------------------------------

Prices are in PAISE (1 INR = 100 paise) and live in
backend/app/services/plans.py:

   PLAN_PRICES_PAISE = {
       PlanType.FREE: 0,
       PlanType.PRO: 99900,        # ₹999
       PlanType.ENTERPRISE: 499900,# ₹4999
   }

Change values then:
   docker compose -f infra/docker-compose.yml --env-file .env build backend
   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend

----------------------------------------------------------------------
3.7  CHANGE PLAN QUOTAS / FILE SIZE LIMITS
----------------------------------------------------------------------

These are in .env (no rebuild needed, just recreate):

   PLAN_FREE_DAILY=10
   PLAN_FREE_MAX_FILE_MB=10
   PLAN_PRO_DAILY=500
   PLAN_PRO_MAX_FILE_MB=200
   PLAN_ENTERPRISE_DAILY=10000
   PLAN_ENTERPRISE_MAX_FILE_MB=2048

   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend worker

----------------------------------------------------------------------
3.8  USE A DIFFERENT GATEWAY (Stripe, PayPal, Paddle…)
----------------------------------------------------------------------

The payments interface is isolated to:
   backend/app/services/payments.py        — Razorpay client + verify
   backend/app/api/subscription.py         — order/verify endpoints
   frontend/src/app/dashboard/subscription/page.tsx — checkout button

To swap providers:

   1. Replace PaymentsService in payments.py with the new SDK
      (e.g. `stripe` Python SDK). Keep the same method names
      (`create_order`, `verify_signature`) so callers don't change.

   2. Update the order/verify endpoints in subscription.py to return
      the fields your frontend SDK expects.

   3. Replace the Razorpay checkout JS in the frontend page with
      the new provider's Elements / Checkout component.

   4. Add the relevant env vars in .env (e.g. STRIPE_SECRET_KEY,
      STRIPE_WEBHOOK_SECRET, NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY).

4. EMAIL (SMTP)
================================================================================

Used by /auth/forgot-password to send password-reset links. Without SMTP
configured, the endpoint returns 200 silently (no email sent). The reset
token still works if you grab it from logs.

----------------------------------------------------------------------
4.1  GMAIL APP-PASSWORD (easiest for dev)
----------------------------------------------------------------------

  1. Enable 2-Step Verification on your Google Account.
  2. https://myaccount.google.com/apppasswords → create one for "Mail".
  3. Add to .env:

       SMTP_HOST=smtp.gmail.com
       SMTP_PORT=587
       SMTP_USER=youraddress@gmail.com
       SMTP_PASSWORD=<the-16-char-app-password>
       SMTP_FROM=youraddress@gmail.com
       SMTP_TLS=true

  4. docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend

----------------------------------------------------------------------
4.2  TRANSACTIONAL PROVIDERS (recommended for production)
----------------------------------------------------------------------

   SENDGRID
       SMTP_HOST=smtp.sendgrid.net
       SMTP_PORT=587
       SMTP_USER=apikey
       SMTP_PASSWORD=<your-sendgrid-api-key>
       SMTP_FROM=verified@yourdomain.com
       SMTP_TLS=true

   AWS SES
       SMTP_HOST=email-smtp.us-east-1.amazonaws.com
       SMTP_PORT=587
       SMTP_USER=<smtp-username-from-ses>
       SMTP_PASSWORD=<smtp-password-from-ses>
       SMTP_FROM=verified@yourdomain.com
       SMTP_TLS=true

   MAILGUN
       SMTP_HOST=smtp.mailgun.org
       SMTP_PORT=587
       SMTP_USER=postmaster@yourdomain.mailgun.org
       SMTP_PASSWORD=<mailgun-smtp-password>
       SMTP_FROM=no-reply@yourdomain.com
       SMTP_TLS=true

----------------------------------------------------------------------
4.3  CHANGE THE EMAIL TEMPLATE
----------------------------------------------------------------------

The HTML template lives in backend/app/services/email.py inside the
build_password_reset_email() function. Edit, then:

   docker compose -f infra/docker-compose.yml --env-file .env build backend
   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend


================================================================================
5. OBJECT STORAGE (MinIO / S3)
================================================================================

All uploaded files (after virus scanning) go into MinIO under unique UUIDs.
The bucket is auto-created on first run.

----------------------------------------------------------------------
5.1  STAY ON MINIO — change credentials
----------------------------------------------------------------------

In .env:

   MINIO_ENDPOINT=minio:9000          # hostname:port (no scheme)
   MINIO_ACCESS_KEY=minioadmin
   MINIO_SECRET_KEY=minioadmin
   MINIO_BUCKET=deepfake-uploads
   MINIO_SECURE=false                  # true if endpoint uses https

Also update the MinIO container's env in infra/docker-compose.yml under
the `minio:` service:

   environment:
     MINIO_ROOT_USER: <NEW_ACCESS_KEY>
     MINIO_ROOT_PASSWORD: <NEW_SECRET_KEY>

⚠️  Changing MINIO_ROOT_PASSWORD on a populated bucket requires deleting
    the volume (loses all uploaded files):
       docker compose -f infra/docker-compose.yml down
       docker volume rm deepfake-detector_minio_data
       docker compose -f infra/docker-compose.yml --env-file .env up -d

----------------------------------------------------------------------
5.2  USE AWS S3 INSTEAD OF MINIO
----------------------------------------------------------------------

The MinIO Python client speaks the S3 protocol, so this is straightforward.

Step 1 — Create an S3 bucket and an IAM user with PutObject/GetObject/
         DeleteObject on it. Note the access key + secret.

Step 2 — In .env:

   MINIO_ENDPOINT=s3.amazonaws.com           # or s3.<region>.amazonaws.com
   MINIO_ACCESS_KEY=AKIA...
   MINIO_SECRET_KEY=...
   MINIO_BUCKET=your-existing-bucket-name
   MINIO_SECURE=true

Step 3 — Comment out the `minio:` service in infra/docker-compose.yml
         and remove `minio` from `depends_on` of backend and worker.

Step 4 — Recreate:
   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend worker

Other S3-compatible providers work the same way:
   - DigitalOcean Spaces : MINIO_ENDPOINT=<region>.digitaloceanspaces.com
   - Backblaze B2 (S3 API) : MINIO_ENDPOINT=s3.<region>.backblazeb2.com
   - Cloudflare R2       : MINIO_ENDPOINT=<acct-id>.r2.cloudflarestorage.com


================================================================================
6. REDIS / CELERY
================================================================================

Redis is used for three purposes:
   DB 0 — generic cache + slowapi rate-limit counters  (REDIS_URL)
   DB 1 — Celery broker (queue)                        (CELERY_BROKER_URL)
   DB 2 — Celery result backend                        (CELERY_RESULT_BACKEND)

----------------------------------------------------------------------
6.1  CHANGE REDIS HOST/PORT (e.g. managed Redis)
----------------------------------------------------------------------

In .env (note the URL format, including the DB number at the end):

   REDIS_URL=redis://default:PASSWORD@redis.example.com:6379/0
   CELERY_BROKER_URL=redis://default:PASSWORD@redis.example.com:6379/1
   CELERY_RESULT_BACKEND=redis://default:PASSWORD@redis.example.com:6379/2

For TLS-only services (Upstash, AWS ElastiCache encryption-in-transit):
   rediss://default:PASSWORD@host:6379/0    (note the double s)

Comment out the local `redis:` service in docker-compose.yml and remove
`redis` from depends_on of backend, worker, flower.

   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend worker flower

----------------------------------------------------------------------
6.2  CHANGE WORKER CONCURRENCY
----------------------------------------------------------------------

In infra/docker-compose.yml under the `worker:` service, adjust the
`--concurrency=4` flag in the command. More = more parallel scans but
more memory used.

----------------------------------------------------------------------
6.3  ADD MORE WORKERS (horizontal scale)
----------------------------------------------------------------------

   docker compose -f infra/docker-compose.yml --env-file .env up -d --scale worker=4

(Use a real Redis or RabbitMQ when going to multi-host.)


================================================================================
7. CLAMAV
================================================================================

Every uploaded file is sent to ClamAV BEFORE being stored. If clamd is
unreachable or returns an error, the upload is rejected (fail-closed).

----------------------------------------------------------------------
7.1  CONFIGURATION
----------------------------------------------------------------------

In .env:

   CLAMAV_HOST=clamav        # hostname/IP of clamd
   CLAMAV_PORT=3310
   CLAMAV_TIMEOUT=60         # seconds; bump for very large files

----------------------------------------------------------------------
7.2  CHANGE MAX SCAN SIZE
----------------------------------------------------------------------

Default clamd max stream size is 25 MB. For larger files, set the
StreamMaxLength in the ClamAV container. In docker-compose.yml under
the `clamav:` service, add:

   environment:
     CLAMAV_NO_FRESHCLAMD: "false"
     CLAMD_CONF_MaxFileSize: 500M
     CLAMD_CONF_MaxScanSize: 500M
     CLAMD_CONF_StreamMaxLength: 500M

Then recreate clamav.

----------------------------------------------------------------------
7.3  DISABLE VIRUS SCANNING (NOT recommended)
----------------------------------------------------------------------

Edit backend/app/security/virus_scanner.py and short-circuit `scan_file`/
`scan_stream` to always return CLEAN. Only do this in dev when you're
sure of your input source.


================================================================================
8. RATE LIMITS, PLAN LIMITS, JWT
================================================================================

----------------------------------------------------------------------
8.1  GLOBAL RATE LIMIT
----------------------------------------------------------------------

In .env:

   RATE_LIMIT_PER_MINUTE=60      # default per-IP / per-user limit
   RATE_LIMIT_BURST=120          # not currently used; reserved

This applies to every endpoint via the SlowAPIMiddleware.

----------------------------------------------------------------------
8.2  PER-ENDPOINT RATE LIMITS
----------------------------------------------------------------------

In backend/app/api/auth.py and detection.py you'll see decorators like:

   @limiter.limit("10/minute")
   def register(request: Request, payload: RegisterRequest, db: DbSession): ...

Edit the strings (e.g. "5/minute", "100/hour") and rebuild backend.

----------------------------------------------------------------------
8.3  JWT TOKEN LIFETIMES
----------------------------------------------------------------------

In .env:

   ACCESS_TOKEN_EXPIRE_MINUTES=60     # short-lived access token
   REFRESH_TOKEN_EXPIRE_DAYS=14       # longer-lived refresh token
   PASSWORD_RESET_EXPIRE_MINUTES=30

   docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend

----------------------------------------------------------------------
8.4  ROTATE THE JWT SECRET
----------------------------------------------------------------------

   1. Generate a strong random string:
        PowerShell:
           -join ((48..57)+(65..90)+(97..122) | Get-Random -Count 64 | %{[char]$_})

   2. Set in .env:
        SECRET_KEY=<the-new-string>

   3. Recreate backend:
        docker compose -f infra/docker-compose.yml --env-file .env up -d --force-recreate backend

   ⚠️  All existing JWTs become invalid — every user must log in again.
